* Осаго общается с core через вебсокеты
* В самом осаго выделил бы наличие кэша с ттл до 2 минут + внутреннии механизмы:
    * асинк таски с запросом предложений в каждую компанию
    * асинк таски возвращают результат в кэш
    * на каждый запрос юзера возвращается результат с кэша по возможности и уходит по сокету, что позволяет не думать об ограничении запросов на вебсокетовой магистрали
* рейт лимитер нужен на заявки от осаго в страховые компании (точнее это запрос предложений по заявке), реализован с истио и подразумевает retry
* предполагается, что внешние средства защиты уже реализованы средствами кубера
* рейт лимит так же есть на магистрали product-aggregator и страховых компаний, лишние запросы приоритезируем
* все рейт лимитеры работают на бакет системе
